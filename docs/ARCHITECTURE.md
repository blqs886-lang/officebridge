# 架构与保真边界

OfficeBridge v1.1.0 使用同一个 JavaScript 引擎服务浏览器与 Node.js CLI。目标是识别可说明证据的风险，并只修改用户明确选择的字体名称；浏览器引擎不调用 Office。可选的本机助手另外调用已安装的桌面 Office 打开文件和导出 PDF。

## 数据流

```text
用户选择的字节
  → ZIP 目录、路径、大小与校验检查
  → XML 解码、解析、内容类型与内部关系检查
  → PPTX / XLSX 只读扫描
  → 报告、风险说明、主动选择的字体建议
  → 对选中 XML 属性作局部替换
  → 重新打包、再次检查、核对未修改部件字节
  → 新副本与变更报告
```

所有处理均在运行应用的电脑上进行。单 HTML 发布物内含脚本、样式、Worker 和合成样例，不依赖远程服务；开发依赖的下载属于另一个过程。

## 主要模块

| 位置 | 职责 |
| --- | --- |
| `src/main.js`、`src/style.css` | 文件队列、报告展示、字体建议选择与下载 |
| `src/ui/pdf-compare.js` | 本机读取两份 PDF，在独立 Worker 解析并按相同物理比例渲染当前页，比较页数、纸张和预览像素 |
| `src/ui/worker.js` | 在浏览器 Worker 内执行检查与修复 |
| `src/ui/reports.js` | 报告展示与导出；将文档提供的字符串作为数据处理 |
| `src/engine/archive.js` | 校验 ZIP 元数据、拒绝不安全路径及资源超限、解压与打包 |
| `src/engine/xml.js` | UTF-8 / UTF-16 解码、XML 检查、保留原 XML 表达方式的属性替换 |
| `src/engine/fonts.js` | 双向的 Windows / Mac 字体名称建议与自定义映射校验；不读取字体文件 |
| `src/engine/pptx.js`、`xlsx.js` | 分格式的只读规则、证据与内容清单 |
| `src/engine/index.js` | 统一接口、SHA-256、修复阻断、变更记录和输出复核 |
| `scripts/cli.mjs` | 批量本地入口；排他输出和错误汇总 |
| `scripts/build-portable.mjs` | 将构建产物内联为独立 HTML，限制网络连接 |
| `src/ui/native-report*.js` | 校验、显示本机助手记录及 PDF 指纹，衔接本地 PDF 对照 |
| `scripts/office-check-windows.ps1`、`verify-windows.ps1` | Windows 文件选择界面、独立工作副本、桌面 Office 打开、PDF 与分页结果 |
| `scripts/office-check-mac.js` | Mac 本机助手，使用系统自动化与已安装的 Office 导出结果 |

数据模型见 [ENGINE-CONTRACT.md](ENGINE-CONTRACT.md)。v1.1.0 提供 `windows-office` 与 `mac-office` 两种目标字体环境；可按用户导入的目标名单筛选建议。完整名单留在当前文件的会话中。

## 修改哪些内容

修复只允许明确选择的字体替换：DrawingML `typeface`，以及 SpreadsheetML 字体名称中的 `val`。按部件与命名空间限定范围，保留主题字体引用及符号、数学字体的必要保护。用户指定映射也不能绕过包级修复阻断。

XML 按原始文本定位属性值，避免整份重新序列化造成无关变化。修改部件保持可识别的原文本编码；未修改部件的内容字节必须与输入一致。原始输入始终作为只读数据，不被覆盖。

引擎不改变公式、数值、日期系统、尺寸、链接目标、动画或媒体，不把对象转成图片，也不删除未知部件。重新压缩会改变 ZIP 的容器表示，因此文件整体 SHA-256 会发生变化；记录原件与副本指纹用于溯源。

## 检查能够说明什么

扫描器报告结构中的声明与引用，不把声明存在等同于实际可见效果。例如主题可能为几十种未使用的脚本预设字体，未知备用字体按部件合并提示；常见普通形状及未应用的主题 3D 样式不会直接被判定为兼容故障。

PPTX 文本检查只处理有限的显式坐标、换行和字号。旋转、分组、继承、真实字形度量和自动换行等未被完整求解；提示必须写明“启发式”。XLSX 公式只做模式检查，不执行或重算；缓存结果也不能证明目标环境中的结果正确。

没有字体二进制或目标电脑环境时，无法确认实际字形覆盖、嵌入字体可用性、媒体编码支持或目标软件行为。报告不存在“兼容分数”，`windowsOfficeTested` 不会因规则检查通过而变为 `true`。

## 拒绝与资源控制

加密、危险 ZIP 路径、重名或名称碰撞、异常压缩结构、大小超限、DTD / 实体及无法安全解析的 XML 会停止处理。签名、宏内容、Strict OOXML 或结构异常在允许安全读取时仅提供检查，禁止修复。

当前上限来自 `archive.js`：文件 100 MiB、解压总量 200 MiB、单条目 100 MiB、单 XML 12 MiB、XML 总量 40 MiB、5,000 个条目；大于 1 MiB 的条目压缩比限制为 300。浏览器另限制每批 20 个文件、合计 250 MiB。

解压只使用已核对的目录元数据。DEFLATE 按 4 KiB 压缩输入分片交给流式解码器，每次回调累计实际输出；超过目录声明时立即停止，不再喂入剩余压缩数据。最终缓冲区按已验证的声明长度预分配，解码器另需临时块缓冲，结束时还必须核对准确长度与 CRC。

若连续超过 128 KiB 压缩输入仍没有产生输出，也会触发资源保护，避免尾随垃圾在解码器内持续积累。此阈值大于 DEFLATE 单个 stored block 的最大长度；使用大量无输出空块的非常规文件也可能被拒绝，因此这不是接受所有合法 DEFLATE 表达方式的承诺。

分片中止减少了伪造小尺寸压缩流耗尽 CPU 的风险。浏览器为每次检查和修复设置 60 秒计时，超时后终止 Worker、拒绝当前请求并重新初始化，让队列中的后续文件继续处理。计时受页面调度影响，CLI 也没有自动超时，因此这不是覆盖所有阶段的硬 CPU 限额。Worker 将计算移出主界面，仍不是恶意文档沙盒。

## 验证层次

1. **自动化测试**：合成文稿、规则边界、异常 ZIP/XML、原件不变及未修改部件保真。
2. **浏览器流程**：macOS Chrome 中的样例、选择、报告、修复和下载；不能替代 Office 渲染测试。
3. **目标环境**：在指定 Mac / Windows 桌面 Office 中打开选定合成文件，导出 PDF，再做编辑、重算或播放验证。已完成与未覆盖的范围分别记录在 [TESTING.md](TESTING.md)，不把单一电脑结果推广为全平台保证。助手步骤见 [NATIVE-OFFICE-CHECK.md](NATIVE-OFFICE-CHECK.md)。
