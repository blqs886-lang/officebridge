# 测试范围与复现方法

OfficeBridge 的结构检查、浏览器操作测试和 Office 实际打开测试是三种不同证据。通过其中一种，不代表另外两种也已通过。本文记录 2026-10-25 开发验证的范围；后续修改应重新运行相关检查，并更新环境与结果。

## 当前验证矩阵

| --- | --- | --- | --- |

| macOS Chrome，开发页面 | `scripts/browser-smoke.mjs` 的 14 组浏览器回归通过，包含自定义字体规则 | 上传、分析、选择、生成、下载、报告和再次导入流程可用；未检测到文档上传或第三方网络请求 | 不是 Windows 浏览器或 Office 的实测结论 |

## 自动检查

开发测试需要 Node.js 22.12 或更新版本。使用锁文件安装依赖后运行：

```sh
npm ci
npm test
npm run build
npm run build:portable
```

`npm test` 运行的是核心与命令行测试；浏览器测试需要单独运行。不要将测试数量写成长期质量承诺：规则会增减，重要的是当次完整输出、失败原因和实际覆盖的行为。

核心与 CLI 的检查包括：

- 字体建议默认不选择，只有有效的选定项目能生成替换；自定义映射的规范化、符号 / 数学 / 图标 / emoji 字体保护、无效目标拒绝。
- 原始文件指纹保持不变；未修改的包部件逐字节保留，记录修改的部件、字体和次数；公式、文本、媒体及可编辑对象不会转成图片或静态数值。
- 损坏 XML、实体 / DTD、不支持的编码、签名、宏、危险内部路径、重复条目、缺失关系、压缩校验和资源上限等情况。
- CLI 明确接受字体替换后才生成副本；报告和副本采用不覆盖的创建方式；中文与空格路径、名称冲突、同名已有成果、坏文件后继续批量处理等情况。

这些检查没有完整实现 OOXML 架构验证，也没有运行文档里的宏、公式、外部连接、嵌入程序或媒体。

## 浏览器回归

脚本使用 Playwright 和已有的浏览器。Playwright 是可选测试工具，不是交付给用户的运行依赖，也不需要为了运行 OfficeBridge 安装它。如果环境已有 Playwright，可以通过 `PLAYWRIGHT_MODULE` 指向其 `index.mjs`；浏览器已安装 Google Chrome 时可指定 `BROWSER_CHANNEL=chrome`，避免另行下载浏览器。

开发页面测试：

```sh
# 先启动开发服务；如果此端口已占用，请换一个端口，并同步修改 APP_URL。
npm run dev -- --port 5173

# 在另一个终端运行。若已能正常 import('playwright')，可以省略 PLAYWRIGHT_MODULE。
PLAYWRIGHT_MODULE=/absolute/path/to/playwright/index.mjs \
BROWSER_CHANNEL=chrome \
APP_URL=http://127.0.0.1:5173/ \
npm run test:browser
```

离线产物测试：先完成上述构建，再把 `APP_URL` 改为本机生成文件的真实 `file://` URL。例如：

```sh
PLAYWRIGHT_MODULE=/absolute/path/to/playwright/index.mjs \
BROWSER_CHANNEL=chrome \
APP_URL=file:///absolute/path/to/officebridge/release/OfficeBridge.html \
npm run test:browser
```

上面是 macOS / Linux 终端的环境变量写法。在 Windows PowerShell 中，用 `$env:APP_URL = '...'`、`$env:BROWSER_CHANNEL = 'chrome'` 等语句设置变量，再运行 `npm run test:browser`。路径中的空格应使用合法的 URL 编码。测试会创建并关闭自己的浏览器实例，不需要操作用户正在使用的浏览器窗口。

当前 14 组浏览器场景如下；实际场景以脚本为准：

1. 首页控件可用，桌面没有横向溢出。
2. 批量上传 PPTX / XLSX，默认没有字体替换被选中。
3. 选择建议后生成 XLSX，下载副本能重新分析。
4. HTML / JSON 报告含修改记录、复查和 Windows 未实测说明；独立 HTML 报告在 320px 及打印样式中无横向溢出，能生成 A4 PDF。
5. 下载副本再次上传，不重复提示已完成的字体替换。
6. PPTX 同样能生成并下载副本。
7. 不支持、空文件和损坏文件得到可读错误。
8. 签名文件保持只读，不允许修复。
9. 不可信文件名和报告字段被转义，下载名称处理 Windows 限制；合成长文件名、字体名与部件路径在独立报告的 320px、390px 和打印样式中可换行。
10. 390px 和 320px 窄屏可操作且无横向溢出。
11. 模拟首个 Worker 卡住，触发超时终止与恢复，后续文件仍能完成检查。测试缩短计时，不实际等待一分钟或消耗 CPU。
12. 单文件 100MB、每批 250MB 的限制在读取内容前执行；测试模拟文件大小，不生成大型测试文件。
13. 自定义字体规则仅影响当前文件；重新检查清除旧选择和旧副本，原文件 SHA-256 不变；手动选择才替换，其他字体保留；报告披露参数；移除规则能恢复内置建议；不安全目标被拒绝。
14. 各测试页面中没有文档上传或第三方网络请求，也没有未处理的页面脚本错误。

结果写入 `work/browser-smoke/result.json`，截图、下载副本和报告也集中保存在该目录。修改后的产物应重新测试，不能直接沿用旧产物的结果。

## 合成大表格的处理验证

可运行 `node scripts/bench-engine.mjs 50000` 复现负载检查；它只在内存中构造合成工作簿，不读取用户文档，也不写入工作簿文件。参数为 1–50,000 行，默认 20,000 行。

2026-10-25 在本次 macOS / Node.js 24.19.0 环境中，50,000 行、150,000 个单元格、50,000 条公式的样例约 1.2 MB，工作表 XML 约 8.3 MB；检查耗时约 2.5 秒，生成并复查副本约 5.7 秒。断言确认原输入未改变，包含公式的整个工作表部件逐字节保持一致。

这是特定合成文件的开发负载结果，不是速度承诺，也不是 Windows Office 的公式、排版或打开验证。真实文件的复杂度、设备性能和浏览器资源限制都会影响耗时。

## 合成示例与 Office 人工检查

仓库提供两个合成示例：

- `public/examples/officebridge-demo.pptx`：2 张幻灯片，包含可编辑文字和图表等对象。
- `public/examples/officebridge-demo.xlsx`：2 个工作表，包含计算公式、中文、前导零和长编号。

界面中的样例按钮使用同一类合成数据；`src/engine/demo.js` 提供嵌入版本。`scripts/create-demo-fixtures.py` 是生成源，需要已有的 `python-pptx` 和 `openpyxl` 环境。普通使用、Node 测试和浏览器测试直接使用已提交的夹具，不需要安装 Python 工具或重新生成夹具。

复核时先在 OfficeBridge 中检查示例，明确选择字体建议后下载新副本，再在目标软件中打开。演示文稿应检查文字是否仍能选择、图表对象是否存在、逐页外观及需要使用的动画和媒体；表格应核对单元格公式、文本编号和打印效果。需要修改单元格验证计算时，只操作合成副本，记录修改前后数值，最后撤销并关闭，不保存测试修改。

对于 Windows，按 [Windows 验证说明](WINDOWS-VERIFICATION.md) 使用可选脚本或人工检查。脚本的“成功打开”记录也不能替代版式比较、编辑、计算和媒体测试。报告中的 `windowsOfficeTested: false` 不会因为 Mac 软件打开成功或脚本语法检查通过而变成 true。
